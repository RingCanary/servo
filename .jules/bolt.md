
## 2024-05-15 - Optimize SupportedPropertyNames to avoid O(N^2) searches and excess allocations
**Learning:** In collection property iteration methods like `SupportedPropertyNames` (used across `HTMLCollection`, `HTMLFormElement`, etc.), using `!vec.contains(&DOMString)` or similar $O(N^2)$ checks for deduplication severely limits performance on large forms/collections. Additionally, performing `.to_string().is_empty()` on an `Atom` forces a heap allocation string conversion where `Atom::is_empty()` performs a native zero-cost check. Lastly, performing `DOMString::from(&*atom)` before verifying uniqueness allocates heavily for discarded strings.
**Action:** When tracking uniqueness during collection generation, use `std::collections::HashSet` with `Atom::clone()` (which is a fast atomic increment for interned strings, unlike string cloning). Defer `DOMString` conversion until the element is verified as novel by the HashSet. Ensure both the vector and hashset are pre-allocated using `Vec::with_capacity(size)`.
