## $(date +%Y-%m-%d) - [O(1) Deduplication with HashSets]
**Learning:** Tracking uniqueness of DOM elements (`Atom` and `&str`) using `Vec::contains` or `Iterator::any()` inside of a loop yields $O(N^2)$ performance. This is severely detrimental in DOM `SupportedPropertyNames` logic where $N$ can scale rapidly. Furthermore, using `.to_string().is_empty()` when checking empty atoms induces unnecessary string allocations.
**Action:** Replace `Vec::contains` and `.any` with a `std::collections::HashSet` to achieve $O(1)$ duplicate checking and $O(N)$ overall time complexity. Always evaluate empty atoms/strings using the native `.is_empty()` instead of `.to_string().is_empty()`. When dealing with `Atom`, it maps nicely to a `HashSet<Atom>` due to extremely cheap interning/cloning properties.
